# 原始部署流程（虚拟机 + 板载计算机路线）

> **路线定位**：这是项目的**第一版部署方案**，在板载计算机（Jetson Xavier NX）上原生安装 ROS1 + Prometheus。
> **后续演进**：板载计算机损坏后，改用 **树莓派 5 + Docker 容器** 复刻同一套环境，见 `01-树莓派5-Docker部署Prometheus+FAST-LIO.md`。
>
> 整理自 `完整配置流程.docx`（原文档从网页/微信文章复制，含排版残留，此处已重写为可执行版本）。

---

## 一、整体环境

| 项 | 配置 |
|---|---|
| 开发/调试环境 | VMware 虚拟机（Ubuntu 20.04） |
| 目标运行环境 | 板载计算机 Jetson Xavier NX（Ubuntu 20.04 + ROS Noetic） |
| ROS 版本 | ROS1 Noetic |
| 无人机上层框架 | Prometheus（阿木实验室 amovlab 开源平台） |
| 通信中间件 | MAVROS（板载机 ↔ PX4 飞控） |

> **为什么先在 VMware 里做**：Prometheus 编译耗时长、依赖多，先在虚拟机里把流程走通、把坑踩完，再一次性搬到板载机，可以避免反复刷板载机系统。

## 二、虚拟机基础环境

### 2.1 VMware Tools 安装

```bash
sudo apt-get update
sudo apt-get install open-vm-tools open-vm-tools-desktop
sudo reboot
```

重启后检查状态：

```bash
sudo systemctl status open-vm-tools
sudo systemctl start open-vm-tools
sudo systemctl enable open-vm-tools
```

### 2.2 SSH 安装与配置

```bash
sudo apt update
sudo apt install openssh-server -y
sudo systemctl start ssh
sudo systemctl enable ssh
```

配置免密登录（把公钥粘进去）：

```bash
cd
mkdir .ssh
vi ~/.ssh/authorized_keys
```

### 2.3 安装 ROS1 Noetic（鱼香 ROS 一键脚本）

```bash
wget http://fishros.com/install -O fishros && . fishros
```

> 该脚本会引导选择 ROS 版本、换源、安装 rosdep，比手动按官网步骤装快很多。

### 2.4 安装 Git 与代理配置（可选）

```bash
sudo apt install git
git config --global http.proxy  http://192.168.184.1:10811
git config --global https.proxy http://192.168.184.1:10811
```

> `192.168.184.1` 是 VMware NAT 网段下宿主机的地址，`10811` 是宿主机上代理软件的端口。换成自己的即可。

## 三、安装 Prometheus 平台

### 3.1 克隆源码

```bash
git clone https://gitee.com/amovlab/Prometheus.git
```

### 3.2 安装 prometheus_mavros

```bash
cd Prometheus/Scripts/installation/prometheus_mavros
chmod +x install_prometheus_mavros.sh
./install_prometheus_mavros.sh
```

新开终端验证：

```bash
roscd mavros      # 能跳转到 mavros 目录即安装成功
```

### 3.3 编译报错处理

**报错 1：wstool 缺失**

```bash
sudo apt install python3-wstool -y
```

**报错 2：rosdep 未初始化（需要翻墙）**

```bash
sudo apt update
sudo apt install proxychains4 -y
sudo vi /etc/proxychains4.conf      # 在末尾加：socks5 127.0.0.1 10811
sudo proxychains4 rosdep init
proxychains4 rosdep update
```

**报错 3：geographic_msgs 等地理数据集缺失**

```bash
sudo apt install ros-noetic-geographic-msgs
sudo proxychains4 geographiclib-get-geoids    egm96-5
sudo proxychains4 geographiclib-get-gravity   egm96
sudo proxychains4 geographiclib-get-magnetic  emm2015
```

> 这三个命令要联网下载几十 MB 的地球模型数据，国内直连很慢，必须挂代理。

### 3.4 编译 Prometheus

```bash
cd Prometheus
chmod +x compile_*
./compile_all.sh
```

### 3.5 配置环境变量

写入 `~/.bashrc`：

```bash
source ~/Prometheus/devel/setup.bash

export GAZEBO_PLUGIN_PATH=$GAZEBO_PLUGIN_PATH:~/Prometheus/devel/lib
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/Prometheus/Simulator/gazebo_simulator/gazebo_models/uav_models
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/Prometheus/Simulator/gazebo_simulator/gazebo_models/ugv_models
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/Prometheus/Simulator/gazebo_simulator/gazebo_models/sensor_models
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/Prometheus/Simulator/gazebo_simulator/gazebo_models/scene_models
export GAZEBO_MODEL_PATH=$GAZEBO_MODEL_PATH:~/Prometheus/Simulator/gazebo_simulator/gazebo_models/texture
```

## 五、Livox Mid-360 雷达

### 5.1 编译 Livox-SDK2

```bash
git clone https://github.com/Livox-SDK/Livox-SDK2.git
cd ./Livox-SDK2/
mkdir build && cd build
cmake .. && make -j2
sudo make install
```

### 5.2 编译 livox_ros_driver2（ROS1 Noetic）

```bash
cd livox_ws/src
git clone https://github.com/Livox-SDK/livox_ros_driver2.git
cd livox_ros_driver2
source /opt/ros/noetic/setup.sh
./build.sh ROS1
```

### 5.3 网络配置

先设置主机 IP（`ens34` 为网卡名，用 `ip addr` 查实际名称）：

```bash
sudo ip addr add 192.168.1.5/24 dev ens34
ping 192.168.1.112          # ping 通说明雷达连上了
```

> `192.168.1.5` 必须与 `MID360_config.json` 里的 `host_net_info` 一致；
> `192.168.1.112` 是雷达的 IP，需与配置文件 `lidar_configs` 处一致。

### 5.4 修改雷达 IP

```bash
vim src/livox_ros_driver2/config/MID360_config.json
# 修改 lidar_configs 处的雷达 IP
```

### 5.5 启动雷达

```bash
cd livox_ws
source devel/setup.bash
roslaunch livox_ros_driver2 rviz_MID360.launch    # 带 RViz 可视化
roslaunch livox_ros_driver2 msg_MID360.launch     # 仅数据
```

## 六、完整启动流程（4 个终端）

```bash
# 终端 1：雷达
roslaunch livox_ros_driver2 msg_MID360.launch

# 终端 2：FAST-LIO 定位
roslaunch fast_lio mapping_mid360.launch

# 终端 3：MAVROS 通信
roslaunch mavros px4.launch

# 终端 4：Prometheus 无人机控制
roslaunch prometheus_uav_control uav_control_main_indoor_mid360.launch
```

## 七、这一版方案的问题

| 问题 | 表现 |
|---|---|
| 依赖板载计算机 | Jetson Xavier NX **损坏后整套环境无法运行** |
| 环境不可迁移 | Prometheus 编译结果绑死在原机器上，换机要重编 |
| 编译耗时长 | `compile_all.sh` 全量编译非常久，且容易卡死 |
| 依赖代理 | rosdep / geographiclib 必须挂代理，现场无网就完蛋 |

**→ 这些正是催生「树莓派 5 + Docker」方案的原因**：把编译好的环境整体打包成镜像，换硬件时直接 `docker import` 就能跑，绕开重新编译。详见 `01-树莓派5-Docker部署Prometheus+FAST-LIO.md`。

## 附：与树莓派方案的差异

| | 原始方案（本文档） | 树莓派方案（01 篇） |
|---|---|---|
| 硬件 | Jetson Xavier NX | 树莓派 5 |
| 系统 | Ubuntu 20.04 原生 | Debian 12 宿主 + Ubuntu 20.04 容器 |
| 环境安装 | 从源码编译 Prometheus | **导入预编译镜像** |
| 依赖获取 | 需代理 | 换国内镜像源 |
| 多窗口管理 | 手动开 4 个终端 | tmux 一键 `start_all.sh` |
| 恢复成本 | 重装重编（数小时） | `docker import`（数分钟） |
