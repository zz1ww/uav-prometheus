## 关于 02 篇（排障笔记）的价值

`02-FAST-LIO排错笔记.md` 记录了两个问题，**每一个都走完了「现象 → 分层排除 → 定位根因 → 提炼判据」的完整链路**：

### 问题一：里程计被判定 Invalid

排查路径（7 步逐层排除）：
```
数据链路是否通？        → rostopic hz 确认 10Hz，排除"没数据"
源码里怎么判定的？      → grep 找到 uav_estimator.cpp:1054-1060
判定依据有哪些分支？    → 超时(return 1) / 协方差错误(return 11) / 位姿误差
协方差是否异常？        → 实测 1e-5~1e-6，远小于阈值 0.05，排除
还有什么分支？          → 发现 vision_pose_error
对比两个位置源          → FAST-LIO z=0.00m vs 飞控 z=4.55m，差 4.5m！
```
**根因**：飞控高度是气压海拔，FAST-LIO 的 Z 是相对原点，基准不同。加剧因素是气压计已拆除。

### 问题二：FAST-LIO 内存崩溃

**关键教训（值得单独记住）**：
> 崩溃后看 `free -h` 会被误导 —— 进程已死，内存早已释放，显示"内存充足"。
> **必须挂监控循环抓崩溃瞬间。**

实测抓到的内存曲线：
```
2.6G → 3.6G 吃满 → 崩溃 → 释放到 212M
```
**根因**：FAST-LIO 体素地图无限累积，拿着无人机到处晃时膨胀最快。

## 值得注意的细节

- **问题一里的坐标系问题**是室内 SLAM + 飞控组合的**经典坑**：激光 SLAM 给的是相对位姿，飞控给的是绝对高度，两者基准天然不同，必须显式对齐。
- **问题二里的"崩溃后看内存会被骗"**是通用调试经验，不限于 FAST-LIO —— 任何看资源用量的排障都适用。
- 两篇笔记都记录了**中间踩的坑**（"第 1 步（踩坑）：被误导"），而不是只写最终答案 —— 这比结论本身更有价值。
