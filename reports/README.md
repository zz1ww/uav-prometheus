## 关键设计（报告中的亮点）

### 以二维码为信息源的任务链

报告第 3.2 节的设计值得注意：**二维码不只是"识别题"，而是整条任务链的信息源**。

```
识别二维码 → 解析出「类别1, 类别2, 降落方向」
                │
                ├─▶ 任务四：决定投放哪个图片靶（类别匹配）
                ├─▶ 任务五：配合特殊靶
                └─▶ 任务七：决定降落方向（left / right）
```

任务之间**不是简单串行，而是有数据依赖**。这是本系统架构上较有想法的一点。

### 视觉与控制的关键桥梁

报告 3.4 节提到一项关键改造：

> 修改开源项目 **SpireCV** 的椭圆检测代码，使其**发布图片靶圆框信息的 ROS 话题**，再编写程序接收图片与圆框信息进行裁剪，用 YOLOv5 分类。

原版 SpireCV 只做检测**可视化**，不对外提供目标位置接口。改造它对外发布圆心坐标，才使"视觉闭环对准"成为可能 —— 这是视觉模块与飞行控制之间的**关键桥梁**。

### 视觉闭环的通用范式

多个任务（投放、穿环、降落）采用了同一套范式：

```
检测目标 → 获取圆心像素坐标 → 判断是否在画面中心
    │                              │
    └──────── 不在 ──▶ 调整位置 ◀──┘
                    在 → 执行动作（下降投放 / 直穿 / 降落）
```

## 客观评价（整理者注）

这份报告**工程数据扎实**，但也存在以下问题：

### 优点

- **量化数据充分**：1850g 实测重量、330mm 卡尺测量、10 次飞行 9 次成功、定位误差 <5cm、悬停续航 8分30秒 —— 有测试轮次、有对比数据。
- **任务参数明确**：每个任务都给出了关键参数（高度、速度、半径、超时）和失败处理策略。
- **安全机制完整**：硬件（桨叶保护、遥控接管、急停）+ 软件（定位/通信/姿态监测、超时跳过、电子围栏）双保险。

### 需要注意的问题

| 问题 | 说明 |
|---|---|
| **团队分工是模板化描述** | 报告中写的是"姓名1（队长）""姓名2""姓名3"，未填真实姓名 |
| **分工描述与实际实现有出入** | 分工提到"A* 全局路径规划""TEB 局部轨迹优化""TensorRT 加速部署"，但 `src/` 中实际代码是**固定航点 + 视觉判断**，未体现 A*/TEB 实现 |
| **部分描述偏理想化** | 如"连续多帧确认机制""电子围栏自动减速返航"，代码中未见对应实现 |
| **重量合规性** | 1.1 节称 1850g "符合规则重量要求"，附录 D 又称"控制在 2500 克以内"，两处口径需统一 |
| **电池倍率与实物不符** ⚠️ | 报告写「60C」，实物电池（图片 `10-电池_5200mAh_4S.jpeg`）标注为 **45C**（脉冲 90C） |
| **图片缺失近半** | 声明 36 个图号，实际仅 18 张图，任务执行过程/轨迹/识别效果类照片基本缺失 |

> **建议**：如需在个人作品集中使用本报告，应如实说明自己负责的模块，避免引用未实现的功能（A*/TEB/TensorRT）作为个人成果。

### 被低估的一张图：场地坐标示意图

`images/16-场地坐标示意图.png` 是报告里**最有技术含量的一张图**，但正文只给了一句"所有坐标均参考比赛规则要求"，没有展开说明。

它实际标注了全部道具的绝对坐标（单位 mm）：

```
起飞点(1500,3000) → 二维码(3300,3000) → 障碍物(5800,3000)
图片靶 ×4: (5100,4600) (3300,4600) (5100,1400) (3300,1400)
特殊靶(7500,2000)  圆环区(7500,4600)
左降落点(1500,1400)  右降落点(1500,4600)
```

**这与 `src/mission_with_vision.py` 里的硬编码坐标是对应的** —— 代码用的是以起飞点为原点的相对坐标，示意图用的是以场地右下角为原点的绝对坐标。两张表对起来看，才能理解代码里那些魔法数字（`1.8 / -1.6 / 3.6`）的来历。

| 报告任务 | 代码阶段标志 |
